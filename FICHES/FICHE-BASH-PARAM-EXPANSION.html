🛡️ Bash : ${N:?message}

Exiger un argument obligatoire en une seule ligne, sans if.

SD=${2:?--dir stress-r500}

🔍 Décortiquons

  • SD= affecte le résultat à la variable SD
  • $2 2ᵉ argument du script
  • :? « erreur si absent ou vide »
  • --dir stress-r500 simple texte d'aide, jamais interprété

⚙️ Ce qui se passe

  • ✅ $2 a une valeur → elle est utilisée
  • 💥 $2 absent/vide → message sur stderr
  • 🛑 Le script s'arrête (code de sortie ≠ 0)
  • Format : script: ligne N: 2: message
FormeRôle$2 non défini$2 = "" (vide)$2 = "abc"
${2:?msg}Erreur si absent ou vide❌ erreur❌ erreur✅ abc
${2?msg}Erreur si absent seulement❌ erreur✅ (vide)✅ abc
${2:-def}Valeur par défautdefdefabc
${2:=def}Défaut + affecte la variabledefdefabc
#!/bin/bash
SD=${2:?--dir stress-r500}
echo "SD=$SD"

$ ./t.sh --dir stress-r500
SD=stress-r500                      # ✅ OK
$ ./t.sh --dir ""
./t.sh: line 2: 2: --dir stress-r500   # 💥 vide refusé avec ":?"
$ ./t.sh --dir
./t.sh: line 2: 2: --dir stress-r500   # 💥 absent

💡 Quand l'utiliser ?

  • Valider un argument obligatoire en 1 ligne
  • Protéger rm -rf "${DIR:?}/" d'une variable vide
  • Exiger une variable d'env : ${API_KEY:?manquante}

⚠️ Pièges

  • Le message ne sert qu'd'indice d'usage, pas de vrai --help
  • Dans un script non interactif, le shell quitte ; en terminal, seule la commande échoue
  • Penser aux guillemets : "${2:?}"
🎯 À retenir : ${N:?msg} = « donne-moi l'argument N, sinon j'affiche msg et je m'arrête ». Avec les deux-points, une valeur vide compte comme absente.
